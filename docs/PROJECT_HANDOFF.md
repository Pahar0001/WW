## 1. Что за проект

**Vela** — премиальная платформа планирования путешествий (RU-интерфейс) с социальным слоем.
Готовые маршруты с планом по дням, конструктор, карты, реальные цены авиабилетов, расчёт трат,
погода, курсы валют, отели, заявки «под ключ» с ИИ-брифом, соцсеть, мессенджер с голосовыми,
сообщество по странам (визы/въезд/посольства), оценки маршрутов, ИИ-консьерж с историей диалогов,
чат поддержки, авторизация + RBAC + админка с метриками и аналитикой, PWA с офлайном, PDF-экспорт,
воскресный email-дайджест и интерактивный 3D-мир `/vela`.

### Принципы, которые нельзя нарушать

1. **Real Data Policy (священна).** Не выдумывать цены, расстояния, время. Реальные данные →
   `VERIFIED` + `source`/`sourceUrl`; расчёты → `ESTIMATED`; неизвестное → `PENDING`. В UI всегда
   видно происхождение и дату значения.
2. **Мягкая деградация.** Нет ключа или внешний API упал → фича молча прячется либо показывает
   честное «нет данных». Страница не ломается никогда.
3. **Ноль `setState` в горячих циклах** (скролл, rAF, игровой кадр) — писать напрямую в `style`
   через refs. См. общий тикер в §7.
4. **Кэш на бэкенде для внешних API** — free-план Render не выдержит прямых запросов.
5. **Приватность по умолчанию:** аналитика анонимна (visitorId, из реферера только хост),
   приватные маршруты не раскрываются даже через погоду, отписка от писем подписана HMAC.

**Монетизация (решение владельца):** партнёрка Travelpayouts (marker в ссылках Aviasales) +
платная услуга «маршрут под ключ» (админ ставит `priceRub` в заявке). Подписка отложена.

**Дизайн:** кинематографический тёмный иммерсив. Палитра — крем `ink` / уголь `paper` /
антикварное золото `aurora`; Inter + Fraunces; тёмная и светлая темы.

## 3. Архитектура

**Runtime-прокси.** Браузер всегда зовёт свой origin (`/api/*`, `/uploads/*`), Next-сервер
форвардит на `BACKEND_URL`. Файлы: `frontend/src/app/api/[...path]/route.ts`,
`app/uploads/[...path]/route.ts`, `lib/proxy.ts`. SSR приватных поездок читает cookie `vela_token`.

```
Браузер → Next.js (web) —proxy→ NestJS (api) → PostgreSQL (+ байты Upload)
                                   ├→ Resend (письма, дайджест)
                                   ├→ Groq (консьерж, ИИ-бриф заявок)
                                   ├→ Travelpayouts/Aviasales (цены билетов)
                                   ├→ Open-Meteo (погода)
                                   ├→ ЦБ РФ (курсы валют)
                                   └→ RSS-ленты (travel-новости)
```

**Кино-hero** (`frontend/src/components/hero/`): секция 420vh + sticky 100svh, скролл = таймлайн
видео. Модули: `ScrollController` (rAF + lerp + IO/RO), `VideoScrubber` (очередь сиков + вотчдог),
`MotionController` (чистые функции таймингов), `ColorGrading` (SVG-фильтр), `PaperNoise`,
`HalftoneOverlay` (выключен, компонент в базе), `HeroVideo` (дирижёр, пишет в style из rAF).
Медиа: `public/hero/thailand.mp4` (47 с, 1080p, 16 МБ) + постер; конфиг `lib/hero-media.ts`.
На `<768px` и при `prefers-reduced-motion` — статичный режим `isStatic` (одна секция с фото):
скраб 16-МБ видео тормозил и конфликтовал с тач-скроллом.

**Глобус** (`components/ui/Hero3D.tsx`): Земля с текстурой NASA Blue Marble
(`public/globe/earth.jpg`, 435 КБ) + процедурные облака + рэлеевская атмосфера. Магнитное
наведение: снап к ближайшей видимой стране в радиусе 56 px; **видимость считается по расстоянию до
камеры, а НЕ по нормали** — тест по нормали браковал приполярные страны, это был баг. Драг
двухосевой: горизонталь — долгота, вертикаль — наклон ±72°. Подпись страны — **HTML-чип внизу
обёртки**: в 3D через `Html` она обрезалась краем секции. Используется в `GlobeSection` (главная)
и `VisitedMap` (профиль). Детали физической модели — §12.4.

**Планировщик дайджеста** — внутрипроцессный (`DigestService`, `OnModuleInit` + `setInterval`
10 мин) с «догоном» через метку в `SystemState`. Внешнего крона нет, а на free-плане Render сервис
засыпает — поэтому догон обязателен.

**Игровой мир `/vela`** — изолированный слой, см. §8.

## 5. Миграции

**Формальных миграций НЕТ.** Каталога `backend/prisma/migrations/` не существует; схема
накатывается `prisma db push` на старте контейнера:

```
CMD npx prisma db push --skip-generate --accept-data-loss && (npm run seed || …) && node dist/main.js
```

⚠️ **`--accept-data-loss` обязателен.** `db push` останавливается на ЛЮБОМ предупреждении —
включая безопасное «добавляется unique-индекс на новой пустой колонке» — и выходит с кодом 1.
Именно это положило четыре деплоя подряд (§12.2). **Любая будущая схема с unique/NOT NULL требует
этого флага — или, что правильнее, перехода на `prisma migrate`.**

**Применено `db push`'ем за всё время:** `TripRating`, `Upload`, `TripOrder` (+`priceRub`),
`User.lastSeenAt`, `User.digestOptOut`, `AssistantThread`, `AssistantMessage`, `TripView`,
`Conversation`, `ConversationMember`, `ConversationMessage`, `VisitedCountry`, `SystemState`,
`Trip.inviteToken`.

Локально накатить схему:

```bash
cd backend
DATABASE_URL='postgresql://vela:change_me_in_production@localhost:5432/vela?schema=public' \
  npx prisma db push --skip-generate --accept-data-loss && npx prisma generate
```

➡️ **Переход на `prisma migrate` (baseline + `migrate deploy` в CMD) — задача №1 в §14.**

### RBAC

Роли `SUPER_ADMIN > ADMIN > ORGANIZER > MEMBER`. `JwtAuthGuard` (`BLOCKED` режется; touch
`lastSeenAt`), `RolesGuard` (SUPER_ADMIN проходит всё), декораторы `@Public`, `@CurrentUser`,
`@Roles`. Первый супер-админ поднимается из `SUPERADMIN_EMAIL` / `SUPERADMIN_PASSWORD`.

**Токен живёт в httpOnly-cookie `vela_token`**, которую ставит обработчик
`frontend/src/app/api/auth/[action]/route.ts` при входе и регистрации; странице он недоступен, а
гвард читает и `Authorization: Bearer`, и cookie. Рядом лежит `vela_session=1` — БЕЗ токена,
только отметка «сессия есть» для интерфейса (`hasSession()` в `lib/auth.ts`). Сессии, выданные до
перехода, продолжают работать из localStorage — `authHeaders()` для них по-прежнему шлёт Bearer.

**Ограничение частоты** — `@RateLimit({ limit, windowMs })` из `common/rate-limit.guard.ts`,
глобальный гвард срабатывает только там, где стоит декоратор. Стоит на `auth/*` (вход 10 / 5 мин,
регистрация 5 / ч, коды и сброс пароля), на платных вызовах Groq (`assistant/chat`,
`orders/refine`), на сообщениях чата и загрузке файлов. Счётчик в памяти процесса — при переходе
на несколько экземпляров его придётся вынести в общее хранилище.

**Публично:** публичные маршруты, сообщество, `travel/*`, `health`, `news/travel`,
`currency/rates`, `weather/trip/:slug`, `digest/unsubscribe`, `trips/invite/:token`.

| `jungle` | юго-запад | густой лес, лагуна |
| `canyon` | запад | плато Красных Стен, разлом до моря |
| `glacier` | северо-запад | лёд, снег, тарн, водопад Ледяные Слёзы |
| `ridge` | север | главный хребет, высшая точка 146 м |
| `volcano` | северо-восток | жерло с лавой, пепел |
| `desert` | восток | барханы, оазис |
| `ruins` | юго-восток | плато, древний город, обрыв |
| `crater` | центр-север | кратерное озеро, исток главной реки |

Отдельно — **Остров Забвения** за проливом (376, 300): пешком недостижим намеренно, это будущая
награда за лодку. Проверяется тестом связности (см. ниже) и помечен `secret`.

**Всё процедурное: ни одной внешней модели, текстуры или HDRI.** Mixamo требует входа в аккаунт
Adobe, сторонние GLB приходят без внятной лицензии, `drei <Environment preset>` тянет мегабайты с
CDN на каждой загрузке. Мир собирается за ~1 секунду и не зависит от сети.

### Решения, которые нельзя откатывать не разобравшись

1. **Рельеф считается один раз в `Float32Array`.** Меш, физика героя, камера, расстановка деревьев
   и мини-карта читают ОДНО поле высот с билинейной интерполяцией. Если семплировать шум напрямую,
   между вершинами сетки (там меш плоский) герой то проваливается, то парит.
2. **Берег НЕ моделируется геометрией.** Поле высот уходит во float-текстуру, водная плоскость
   делает `discard` там, где земля выше уровня воды. Отсюда бесплатно: точная кромка в любой бухте,
   цвет по глубине, пена ровно на отмели.
3. **Водопады, каньон и перевалы в валы кальдер ВЫРЕЗАНЫ в рельефе намеренно** (`RIVERS`, `CANYON`,
   `TRAILS`, `FLATS`). Ждать нужную вертикальную стену от шума бессмысленно. Профиль русла задан
   руками и монотонно убывает — глаз мгновенно ловит «реку, текущую в гору».
4. **Тропы выравниваются СЕТЬЮ, а не по одной** (`gradeTrails`). Развилки записаны в разных трассах
   одной парой координат и считаются ОДНИМ узлом. Пока каждая трасса грейдилась отдельно, в общей
   точке они приходили к разным высотам (133 против 108) и на стыке вставала ступень в 25 м.
5. **Полотна троп смешиваются по весам, а не накладываются по очереди** (`heightAt`). У развилки
   коридоры перекрываются; при последовательном наложении побеждала трасса, стоящая в массиве
   позже, и давала провал с последующей стенкой в 61°.
6. **Вал кальдеры — гарантированный минимум высоты, а не прибавка** (`Basin.rimUp`). Прибавка
   работает на равнине, но чаша на склоне всё равно вытекает под гору: у тарна вал был на 8 м НИЖЕ
   собственного зеркала.
7. **Ни один узел тропы не лежит внутри чаши из `BASINS`.** Тропа прорезает рельеф, но НЕ убирает
   воду — герой шёл бы по дну озера. Четыре трассы из восьми проходили через зеркало, включая
   финал вулканической — в центр жерла, то есть в лаву.
8. **Площадки (`FLATS`) не накрывают центры чаш**: они применяются ПОСЛЕ вырезания кальдер и просто
   засыпают их. Три озера из пяти превращались в ровное плато.
9. **Рельеф нарезан на 100 чанков с двумя LOD** (`TerrainMesh.tsx`). Единым мешем это 630 000
   треугольников, которые рисуются целиком даже когда 90 % за спиной. Отдельные меши отсекаются по
   пирамиде видимости бесплатно, дальние рисуются вчетверо более редкой сеткой. Стыки закрыты
   «юбкой» — кольцом вершин, опущенным на 2 м.
10. **AO запечён в цвета вершин**, SSAO-прохода нет: ноль кадрового времени вместо 2–4 мс.
11. **Рябь воды считается НА ПИКСЕЛЬ** (`waveNormal`), в геометрии осталась только длинная зыбь.
    Сетка воды растянута на весь мир (3.7 м между вершинами у океана), и рябь с длиной волны 7 м
    попадала на неё тремя точками на период — вместо воды шли ровные полосы шириной с дом. Рябь
    гаснет с расстоянием: иначе её период становится меньше пикселя и даёт муар.
12. **`FOG_DENSITY` объявлена ОДИН раз** в `Sky.tsx`. Собственные шейдеры воды не получают туман
    сцены автоматически и считают его сами; пока константа была записана дважды, горы растворялись
    в дымке, а океан у горизонта оставался синим.
13. **Тень солнца — 62 м вокруг героя** и едет с ним. Накрыть материк (840 м) картой 2048 значило бы
    41 см на пиксель: тени превратились бы в лестницы.
14. **Газон живёт в диске 26 м вокруг героя** и пересаживается, когда тот отходит на 3 м. Засеять
    весь материк — либо не видно под ногами, либо миллионы полигонов за кадром.
15. **Сборка мира уступает управление браузеру порциями по времени** (12 мс на видимой вкладке).
    На СКРЫТОЙ вкладке `requestAnimationFrame` не вызывается вовсе, и сборка замирала до
    возвращения пользователя — там уступаем через `MessageChannel`, который в фоне не придушен.
16. **Прогресс игрока** — в `localStorage['vela_island_progress']` (открытые регионы + артефакты).

### Сюжет, дневник и задания

Сюжет: Орден Картографов начертил карту всего мира, её разорвало на восемь
частей и растащило по восьми землям. Игрок собирает **Карту Мира Vela** —
восемь фрагментов, по одному на регион; каждый открывает главу.

```
story.ts        8 глав, 8 фрагментов, 11 записей дневника, 3 экрана вступления
quests.ts       12 заданий; цель — ДАННЫЕ, у каждой есть kind
quest-runner.ts ЕДИНСТВЕННЫЙ вычислитель всех типов целей, зовётся раз в кадр
hud/Story.tsx   вступление, экран главы, трекер цели, подсказка действия, дневник
world/QuestObjects.tsx  фрагменты, доски, знаки, ключи, места работ, точки съёмки
```

Пять типов целей: `reach` (прийти), `pickup` (подобрать), `fragment` (ссылка на
фрагмент), `photo` (встать и нажать E), `work` (удерживать E, требует собранных
предметов задания). **Добавление задания — это правка данных в `quests.ts`,
игровой цикл не трогается.**

Решения, которые нельзя откатывать не разобравшись:

1. **Фрагменты описаны ОДИН раз** — в `story.ts`. Сначала они были и записью
   сюжета, и целью задания с теми же координатами: два независимых сборщика на
   одном объекте, счётчики расходились. Цель вида `fragment` лишь ссылается.
2. **Цель зачитывается, даже если задание «не выдано»**: мир открыт с первой
   минуты, и игрок вполне подберёт доску до того, как узнает про мост. Отказать
   ему — значит наказать за любопытство, ради которого игра и сделана.
3. **Пауза ВЫЧИСЛЯЕТСЯ** (`isFrozen`), а не хранится флагом. Карточка региона и
   экран главы открываются в одной точке; пока каждое окно ставило `paused`
   само, закрытие первого снимало паузу при висящем втором — герой уходил
   гулять за модальным окном.
4. **Пока открыто окно, задания не обсчитываются**: иначе E срабатывало сквозь
   дневник — открыл журнал, нажал E, получил снимок места под ногами.
5. **Нажатие действия буферизуется на 180 мс** (`input.actionAt`), как прыжок:
   короткий щелчок целиком укладывается между двумя кадрами и иначе теряется.
6. **Код клавиши достраивается по `key`, если `code` пуст** (`keyCodeOf`).
   Управление держится на `event.code` осознанно — это физическая клавиша, и
   WASD работает в любой раскладке. Но экранные клавиатуры, часть программ
   доступности и синтетические события `code` не заполняют, и игра МОЛЧА не
   реагировала на нажатия.
7. **Настил моста — на 0.45 м выше земли в точке переправы**, а не выше трассы.
   Поле высот — одна поверхность, «тропа поверх реки» в нём невыразима, поэтому
   переправа это брод. При настиле на 1.3 м игрок проходил ПОД собственным
   починенным мостом по колено в воде.
8. **Сохранение версии 2 с миграцией с версии 1.** У игры есть игроки, и в их
   localStorage лежит `{discovered, artifacts}` без поля `v`. Отсутствие `v`
   трактуется как версия 1, а не как мусор, — иначе обновление сайта обнуляло
   бы чужой прогресс.

**Проверка сюжета — `frontend/scripts/check-story.ts`** (мгновенная, без рельефа):
уникальность идентификаторов, одна цель не в двух заданиях, все ссылки ведут в
существующие сущности, каждая глава чем-то открывается, каждая запись дневника
чем-то выдаётся, нет циклов в предусловиях.

⚠️ **Оговорка про проверку в браузере:** на СКРЫТОЙ панели превью
`requestAnimationFrame` придушен, игровой цикл идёт ~0.3 кадра в секунду. Любая
буферизованная по времени механика (нажатие действия, 180 мс) в таком режиме не
воспроизводится, и показания FPS бессмысленны. Проверять логику там нужно по
частям: событие → `input`, затем `input` → результат.

### Проверка мира — `frontend/scripts/check-world.ts`

```bash
cd frontend && node --no-warnings scripts/check-world.ts
```

Гоняйте ПОСЛЕ ЛЮБОЙ правки рельефа, троп, рек или координат регионов. Скрипт собирает поле высот
вне браузера и печатает:

* время сборки и память по тирам, стоимость `heightAt`;
* экстремумы высот и долю суши (сейчас 146 м и 64 %);
* **чаши** — дно, зеркало и минимум вала ПО КРУГУ: где вал ниже зеркала, озеро вытечет
  (лучи, идущие по руслу, пропускаются — сток это законный проран);
* **реки** — монотонность профиля и узлы, лежащие на гребне вместо русла;
* **тропы** — максимальный уклон вдоль трассы (предел ходьбы 0.50) и участки под водой;
* **связность** — заливка от спавна: сколько процентов проходимых клеток достижимо и достижимы ли
  КАЖДЫЙ регион, артефакт, фрагмент карты и КАЖДАЯ цель КАЖДОГО задания (сейчас 60 точек);
  намеренно недостижимое перечислено списком с причиной — и проверяется в обе стороны, потому что
  «стало достижимым» тоже поломка (замкнулся пролив);
* **мосты** — зазор между настилом и землёй (норма 0.2…0.8 м);
* ASCII-карту материка.

Восемь настоящих багов этой правки найдены именно им, а не глазами: суша на 97 % карты без океана,
вершина 266 м при заявленных 152, четыре тропы с уклоном до 88 % (в том числе по дну озера и в
центр лавы), три пересыхающих озера, тропа, засыпавшая оазис, и река, текущая в гору на последних
ста метрах. На глаз в мире 840 × 840 м не видно ничего из этого.

**Отладка (только dev):** `window.__vela = { char, hf, input, live, to(x, z) }`.
Например `__vela.to(74, 44)` — телепорт к руинам, `__vela.input.lookX = -30` — поворот камеры.

## 12. Грабли — читать до работы

### 12.1. Деплой падает на `npm install` (стоило красного деплоя)

`frontend/Dockerfile` копирует **только `package.json`** и делает `npm install` — то есть
**`package-lock.json` при сборке образа игнорируется**, зависимости разрешаются заново. Из-за этого
`"postprocessing": "^6.35.6"` на Render превращался в `6.39.x`, который требует `three >= 0.168`,
а проект жёстко держит `three@0.160`. Конфликт пиров → `npm install` выходит с кодом 1 → красный
`vela-web`, лог обрывается на `Dockerfile:11`. Локально не воспроизводится: там лок-файл есть.

**Правило: любая зависимость с peer на `three`, `react` или `@react-three/fiber` пишется точной
версией, без каретки.** Проверять командой из §11.

### 12.2. `prisma db push` без флага (четыре красных деплоя подряд)

На старте контейнера push останавливался на предупреждении «unique constraint on `Trip.inviteToken`
… this will fail» и выходил с кодом 1. Лечение — `--accept-data-loss` в `CMD` (колонка новая и
пустая, NULL в Postgres-unique не конфликтуют). См. §5.

### 12.3. Кэш докер-слоя (стоило ~3 часов)

Деплои `vela-api` шли «зелёными» за ~1 м 25 с, но образ собирался из закэшированного слоя
`COPY src` со старым кодом: chats и news работали, weather и currency отдавали 404. Лечение:
`ENV BUILD_REV=…` перед `COPY src` в Dockerfile — бампнуть значение = принудительная инвалидация.
Альтернатива в панели: Manual Deploy → «Clear build cache & deploy».

⚠️ **Диагностика:** в списке деплоев Render смотри **именно `vela-api`** — у `vela-web` деплои
могут быть зелёными, пока API падает. Симптом «код запушен, на сайте нет фичи» = красный деплой api.

### 12.4. Битый ассет вместо настройки (глобус)

`public/globe/clouds.jpg` оказался **пустым файлом: 1600×800 сплошного белого**, ни одного пикселя
темнее 255. Аддитивный слой из него намазывал ровную белую пелену на весь диск — это и читалось как
«туманность». Файл удалён; облака теперь считаются процедурно (`makeCloudAlphaMap` в `Hero3D.tsx`).

Мораль: **если картинка выглядит «не так», сначала проверь сам ассет попиксельно**, а не крути
настройки материала.

Заодно в глобусе: облака работают маской прозрачности на белом **освещённом** слое (настоящие
облака ничего не излучают и гаснут на терминаторе); маска воды строится в шейдере по разнице
каналов Blue Marble, и внутри неё шероховатость падает до 0.11 — отсюда блик солнца по океану;
атмосфера — френель-ободок, гаснущий на ночной стороне; тумана, гало, лучей и пыли нет — в вакууме
рассеивать нечего.

### 12.5. Dev-сервер и `next build` в одной папке

**`next build` во `frontend/`, пока там же работает `next dev`, ломает dev-сервер** — страница
отдаёт пустой белый экран с нетронутым 300×150 canvas. Останавливай dev до сборки.

### 12.6. Service worker отдавал чанки удалённой сборки — ИСПРАВЛЕНО (`7e119db`)

Симптом: **`Application error: a client-side exception has occurred`** на странице, при том что
сервер отдаёт корректный HTML и все чанки резолвятся (проверять так:
`curl -s https://velatrips.ru/vela | grep -o '/_next/static/[^"]*\.js'` и пройтись по каждому).

Две причины, обе устранены:

1. **Версия кэшей в `public/sw.js` была захардкожена `'v1'`.** Обработчик `activate` удаляет «все
   кэши, кроме текущих», но после деплоя текущие имена совпадали со старыми — чистка была мёртвым
   кодом. В кэше `PAGES` навсегда оставался HTML, отданный ДО деплоя, со ссылками на чанки со
   старыми хешами, которых на сервере уже нет.
   Теперь версия приходит из адреса регистрации `/sw.js?v=<BUILD_ID>`; `BUILD_ID` задаётся в
   `next.config.js` (`RENDER_GIT_COMMIT`, иначе время сборки) и прокидывается в клиент через
   `NEXT_PUBLIC_BUILD_ID`. Смена адреса SW → новый экземпляр → `activate` вычищает кэши прошлой
   сборки. Кэш сохранённых поездок `vela-trips` намеренно вне версии и переживает деплой.
2. **На localhost SW от докер-сборки травил dev-сервер.** Докер поднимает ПРОД-сборку на том же
   `localhost:3000`, регистрирует SW и оставляет его жить; затем на этот адрес встаёт dev-сервер, у
   которого имена чанков БЕЗ хешей, а статика отдаётся cache-first. Теперь в development
   `PwaProvider` не просто не регистрирует SW, а **снимает** его и удаляет кэши `vela-*`
   (кроме `vela-trips`).

⚠️ `BUILD_ID` кладётся в `process.env.__VELA_BUILD_ID` и переиспользуется: `next.config.js`
вычисляется НЕСКОЛЬКО раз за сборку (отдельные процессы компиляции сервера и клиента), и
`Date.now()` давал там разные значения — идентификатор сборки Next расходился с
`NEXT_PUBLIC_BUILD_ID`.

Если симптом всё же повторится у пользователя со старым SW: DevTools → Application →
Service Workers → Unregister, затем Storage → Clear site data.

### 12.7. `next build` проверяет типы в `frontend/scripts/` (стоило красного билда)

Скрипты проверок запускает НАПРЯМУЮ Node (`node --no-warnings scripts/check-world.ts`), поэтому в
них расширение `.ts` в пути импорта обязательно. Настройки Next это расширение запрещают:
`tsc --noEmit` проходил, а `next build` падал на файле, которого нет в бандле. Папка `scripts`
исключена в `frontend/tsconfig.json` — **не убирать исключение**.

### 12.8. Скрытая панель превью душит `requestAnimationFrame`

На скрытой панели игровой цикл идёт ~0.3 кадра в секунду. Следствия:
- **показания FPS бессмысленны** (см. также 12.9);
- **любая механика с временным буфером не воспроизводится** — например нажатие действия живёт
  180 мс и истекает раньше следующего кадра. Проверять по частям: событие → `input`, затем
  `input` → результат, а не «нажал и посмотрел на итог»;
- сборка мира это уже учитывает: на скрытой вкладке уступает через `MessageChannel` (§8).

### 12.10. Юридический слой: три места, где легко сломать бесшумно

1. **Версии документов объявлены ДВАЖДЫ** — `frontend/src/lib/legal/versions.ts` и
   `backend/src/modules/legal/versions.ts`. Один общий файл невозможен: Docker собирает `frontend`
   и `backend` из РАЗНЫХ контекстов (`render.yaml`), файл из корня репозитория не попадёт ни в
   один образ. Если списки разъедутся, человек увидит на экране одну редакцию, а в базу как
   доказательство ляжет другая — и согласие перестанет что-либо доказывать. Ловится
   `scripts/check-legal.ts`, гонять перед пушем.

2. **Документы обязаны описывать то, что код делает на самом деле.** Перечень cookie в
   `lib/legal/cookies.ts` собран по ключам `vela_*`, список третьих лиц в `privacy.ts` — по
   исходникам бэкенда (Render, Resend, Groq, Travelpayouts). Добавили внешнюю интеграцию или новый
   ключ в браузере — правьте документ ТЕМ ЖЕ коммитом. Политика, разошедшаяся с кодом, хуже
   отсутствующей: она вводит в заблуждение.

3. **`acceptTerms` больше НЕ идемпотентен** и это намеренно. Прежняя версия при непустом
   `termsAcceptedAt` молча возвращала «уже принято», поэтому новую редакцию документов никто бы не
   подписал — гейт молчал бы. Теперь он смотрит на `pendingConsents` из `/auth/me`.

⚠️ Реквизиты оператора в `lib/legal/operator.ts` — ЗАГЛУШКИ. Пока они не заменены, все три
страницы показывают заметное предупреждение «черновик», а `check-legal.ts` печатает
предупреждение. После заполнения поднять версии документов в ОБОИХ файлах версий.

### 12.11. CSP: `'unsafe-inline'` в script-src оставлен осознанно

Next вставляет в страницу собственные встроенные сценарии (загрузчик, поток данных), плюс наш
выбор темы до первой отрисовки в `layout.tsx`. Убрать директиву можно только вместе с переходом на
nonce через middleware — это отдельная работа. Остальные директивы при этом работают и проверены
живьём на прод-сборке: главная, `/privacy`, `/register`, `/profile/settings` и `/vela` (three.js,
воркеры, видео) грузятся без единой ошибки в консоли.

### 12.12. Логистика: цены наземного транспорта НЕ заполняются

Техзадание просило показывать «стоимость, время, удобство, ссылку» для поездов, автобусов и
такси. `priceNote` и `durationNote` в `ground-transport.ts` ПУСТЫ намеренно: цены зависят от даты,
класса и направления и меняются в разы, а §1 запрещает придумывать цены и время. В справочнике
лежит то, что устойчиво и проверяемо, — перевозчик и его официальный адрес; цифры человек видит по
ссылке, на свою дату. Заполнять эти поля можно ТОЛЬКО вместе с `source`/`sourceUrl` и переводом
`dataStatus` в `VERIFIED`. Интерфейс честно пишет «смотрите у перевозчика» — не «чинить».

Реальные цены в разделе одни — авиабилеты из Aviasales, и они помечены VERIFIED с временем
котировки.

### 12.13. Физика: «отпустил управление» ≠ «остановись»

При добавлении сцепления скольжение на льду сначала не работало вовсе: показатель `slide` рос,
а герой стоял. Причина — разгон к целевой скорости применялся всегда, и при отпущенном управлении
цель равна нулю, то есть та же формула работала мощнейшим тормозом: на льду 4.2 м/с² против 2.0
м/с² от склона. Теперь разгон применяется, только пока управление нажато (или герой в воздухе), а
без него работает лишь трение, зависящее от сцепления.

Измерено на прод-сборке через `__vela.step(dt, steps)` — шаг физики вручную, потому что на скрытой
панели превью `rAF` придушен (§12.8) и «посмотреть, как скользит» там невозможно. Тормозной путь с
5 м/с на ровном месте: дюна 0.56 м, пепел 0.43, снег 0.41, галька 0.35, лес 0.34, глина 0.30 —
монотонно по `SURFACE_GRIP`. Лёд на склоне 0.36 сползает 1.9 м за 3 секунды без единого нажатия;
остальные поверхности не сползают вовсе.

### 12.14. `pointerleave` в React синтезируется из `pointerout`

Кнопка действия на тач отпускалась не всегда: React строит `onPointerLeave` из `pointerout`, и
одного `leave` мало. Обработчики висят на `up`, `cancel`, `out` и `leave` разом — палец,
соскользнувший с кнопки, обязан считаться отпущенным, иначе работа на месте продолжает
выполняться сама.

### 12.15-бис. CSP убила ВСЕ чужие картинки через service worker

Вторая и более коварная жертва той же CSP. Воркер наследует политику того
ответа, которым отдан его скрипт, перехватывает КАЖДЫЙ GET и переспрашивает его
своим `fetch()` — а `fetch` внутри воркера подчиняется `connect-src`. С
`connect-src 'self'` любой исходящий запрос в воркере обрывался, и на проде
разом умерли обложки маршрутов с Викимедиа и плитки карт CARTO.

Диагностировать тяжело, потому что улик почти нет: запроса в сеть НЕТ, ошибки в
консоли страницы НЕТ, `<img>` просто остаётся с `naturalWidth: 0`. Локально не
воспроизводится вовсе — воркер регистрируется только в production. Ключ к
разгадке: своя картинка грузится, любая чужая — нет, включая заведомо рабочую.

Вылечено раздельными правилами в `next.config.js`: странице `connect-src 'self'`
(она и правда никуда наружу не ходит), воркеру — `connect-src 'self' https:`.
Отрицательный просмотр вперёд в `source` обязателен: попади на `/sw.js` ДВА
заголовка CSP, браузер применил бы пересечение и строгая всё равно победила бы.

⚠️ Мораль ко всем 12.15: **CSP ломает не там, где смотришь.** После любой правки
политики проверять страницу маршрута (карта + фото), `/vela` и загрузку файлов —
и проверять на ПРОДЕ, потому что воркера в dev нет.

### 12.15. CSP убила карты — проверять НЕ ТОЛЬКО изменённые страницы

`TripMap` подгружал Leaflet тегами с unpkg.com, а `script-src 'self'` (§12.11) это молча убил:
карта переставала грузиться на КАЖДОЙ странице маршрута, в консоли оставалось одно сообщение о
блокировке. Поймано только через сутки, потому что при выкатке CSP я прошёл главную, `/privacy`,
`/register`, `/profile/settings` и `/vela` — то есть ровно те страницы, которые менял, а карта
живёт там, куда я не заглянул.

Вылечено переносом Leaflet в свой бандл (`npm i leaflet`, динамический импорт — библиотека трогает
`window` на верхнем уровне и падает на отрисовке на сервере). **Не возвращать CDN, дописав unpkg в
разрешённые источники:** своя копия оставляет CSP строгой, снимает зависимость от чужого сервиса и
не отправляет IP посетителя в стороннюю сеть доставки, которой нет в политике обработки ПДн.

Мораль шире: любое изменение политики, заголовков или прокси проверять на странице с картой, на
странице с загрузкой файлов и на `/vela` — там живут все внешние ресурсы.

### 12.16. Время вылета читать ИЗ СТРОКИ, а не через `new Date()`

Aviasales отдаёт `departureAt` с местной зоной вылета: `2026-10-12T00:35:00+03:00`. Это то, что
напечатано на билете. Разобрав его датой, мы пересчитаем время в часовой пояс сервера и покажем
«вылет в 21:35» там, где человек увидит 00:35. Час берётся регуляркой по строке — см.
`earliestDeparture` в `logistics.service.ts`.

⚠️ Времени прилёта ДОМОЙ вывести неоткуда: в выдаче есть время вылета обратно и `durationMin`
суммарно за оба плеча, но нет ни времени по плечам, ни часовых поясов. Поэтому блок «Возвращение
домой» сформулирован условием («если прилетаете ночью»), а не подставляет вычисленный час. Не
чинить домножением на 0.5 — это будет гадание.

### 12.9. Прочее

- **dev StrictMode дублирует imperative-DOM эффекты** (`ScrollRail`) — cleanup обязан удалять
  созданные узлы.
- **`pointsMaterial` без карты рисует КВАДРАТЫ** — самый заметный признак дешёвой графики.
  Всем частицам давать `makeGlowTexture()` из `fx/particles.ts`.
- **`overflow: hidden` для mask-reveal при `line-height < 1`** (наш `.display-1` = 0.98) **срезает
  выносные элементы кириллицы** — «у», «р», «д», «ц», «щ». В маске строки стоит
  `padding-bottom: 0.2em` + компенсирующий отрицательный margin.
- **`.spotlight::before` должен быть `z-index: -1`.** При `z-index: 0` позиционированный `::before`
  рисуется поверх контента и приглушает текст.
- **Tone mapping (ACES) живёт на рендерере, а не в композере** — иначе на low-тире (композера нет)
  картинка отличается от mid/high.
- **Замеры FPS в неактивной панели браузера врут.** Там душится всё: и `requestAnimationFrame`, и
  `setTimeout` (проверено: 2 срабатывания в секунду при `hasFocus: false`). Мерить только на
  активной вкладке; при настоящем падении FPS таймеры идут нормально.
- **Preview-MCP:** скриншоты иногда чёрные или сжатые после resize — проверяй DOM/JS-замерами;
  скролл может сбрасываться МЕЖДУ вызовами `javascript_exec` (внутри одного вызова стабилен).
- **Логиниться ассистент не может** — админку и соцстраницы проверяет владелец.
- **Окна игры внутри HUD требуют `pointer-events-auto`.** Контейнер HUD стоит с
  `pointer-events-none`, чтобы мышь проходила к сцене; модальное окно без этого класса выглядит
  живым, но кнопки в нём не нажимаются вовсе — игра кажется зависшей.
- **`torusGeometry` строится в плоскости XY, то есть СТОЯ.** Всё, что должно лежать (поручни,
  кольца на земле, розы ветров), обязано иметь `rotation={[-Math.PI/2, 0, 0]}`. Поручень смотровой
  без поворота полгода стоял пятиметровой аркой.
- **Управление держится на `event.code`** (физическая клавиша → WASD в любой раскладке), но `code`
  заполнен не всегда: экранные клавиатуры, часть программ доступности и синтетические события шлют
  только `key`. Достраивать код через `keyCodeOf` из `player/controller.ts` — иначе игра МОЛЧА не
  реагирует на нажатия.

## 15. Рекомендации по дальнейшей разработке

**Порядок работы, который себя оправдал:**

1. Начинай с этого файла и `git log --oneline -15`.
2. Крупную задачу веди так: схема БД → `db push` → бэкенд-модуль → typecheck → клиент → UI.
3. `npx tsc --noEmit` после каждого блока; прод-сборки — перед пушем.
4. **Проверяй вживую** (curl эндпоинтов + preview-MCP для UI), а не «по коду».
5. **Численно проверяй то, что генерируется — это главный вывод последних сессий.** Рельеф,
   профили троп, координаты регионов и связность сюжета отлаживаются скриптами на Node с прямым
   импортом `.ts` (Node 26 стирает типы сам). В мире 840 × 840 м глазами не видно ничего: восемь
   настоящих багов первого коммита (суша на 97 % карты без океана, вершина 266 м вместо 152, четыре
   непроходимых тропы — одна по дну озера, другая в центр лавы, три пересыхающих озера, река,
   текущая в гору) нашёл скрипт, а не просмотр сцены. **Если добавляешь генерируемую сущность —
   добавь ей проверку в `check-world.ts` или `check-story.ts` в том же коммите.**
6. **Прогоняй `next build`, а не только `tsc`.** `tsc --noEmit` проходил, а `next build` падал
   (§12.7) — это красный деплой. Порядок: остановить dev (§12.5) → `rm -rf .next` → `next build`.
7. Коммит на каждый законченный блок; в теле — что и **почему**.

**Что я делал бы следующим (по игре):** пункт 2 спецификации — физику. Она дешевле остальных,
потому что `SURFACE_GRIP` уже посчитан и лежит без дела, и при этом сильнее всего меняет ощущение:
сейчас управление «игрушечное», лёд не скользит, вода не тормозит. Сразу за ней — пункт 8
(мобильные), потому что **на телефоне сейчас физически недоступны съёмка и работы: кнопки действия
на тач нет**, то есть часть заданий непроходима. Затем NPC: они дают рамку для всего остального
контента и в структуре заданий под них уже оставлено место.

**Что я делал бы следующим (по платформе):** `prisma migrate` — единственный долг, который с ростом
схемы дорожает нелинейно и уже дважды ронял прод.

**Чего не делать:**
- не обновлять `three`/`fiber`/`drei`/`postprocessing` (§2);
- не добавлять библиотеки плавного скролла (§7);
- не тащить внешние 3D-модели и HDRI (§8);
- не коммитить `backend/dist-seed/`, `backend/package-lock.json`,
  `frontend/tsconfig.tsbuildinfo`, `.env` — они уже в `.gitignore`.
